# Chat GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `llm gui`, a local browser chat front end over the existing `ChatSession`, with saved/resumable chats, collapsible thinking blocks, and rendered markdown.

**Architecture:** A Litestar app served by Granian wraps the existing `ChatSession`/`Registry`/`catalog`/web toolbox. Each reply runs in a worker thread as a server-side task that buffers events and persists messages to per-chat JSONL files; the browser (plain HTML/CSS/JS, no build step) attaches to a reply over fetch-streamed SSE, so switching chats never cancels one. The terminal REPL is untouched.

**Tech Stack:** Python 3.14, Litestar, Granian, existing `openai`/`httpx`; browser side `marked` + `DOMPurify` (vendored). Tests: pytest with the fakes in `tests/conftest.py`; ruff and pyrefly.

**Spec:** `docs/superpowers/specs/2026-10-18-chat-gui-design.md`. Read it first; this plan only records decisions the spec leaves open.

**Commits:** Krish commits his own work in this repo. Tasks end with a checkpoint (tests + lint green), not a commit step.

## Global Constraints

- `requires-python = ">=3.14"`; dependencies via `uv add` (never edit `uv.lock` by hand). If a source build is ever needed: `CC=/usr/bin/cc CXX=/usr/bin/c++ uv ...`. Never touch `~/.local/bin/cc`.
- Code style: `from __future__ import annotations`, full type annotations, module docstrings, ruff line length 88, pyrefly clean (`uv run ruff check`, `uv run ruff format --check`, `uv run pyrefly check`).
- `llm chat`, `ask` and all other existing commands behave exactly as before; existing tests keep passing.
- No Node, no build step, no CDN at runtime: `marked` and `DOMPurify` are committed pinned copies.
- Server binds `127.0.0.1` only; API keys never leave the server.
- Chats live in `$XDG_DATA_HOME/llm/chats/<id>.jsonl` (default `~/.local/share`), one JSON object per line, append-only, each with a `type` of `meta`, `settings` or `message`.
- Sidebar title is the first user message trimmed to about 60 characters; no model call.
- Python-side tests use `uv run pytest`; every new behaviour gets a test written first and seen failing.

## Review Focus

Failure modes the spec implies, each pinned by a test in the task named:

1. A chat id such as `../../etc/passwd` must never touch files outside the chats directory (Task 3).
2. One corrupt, empty, or foreign file in the chats directory must not stop the sidebar from listing the others (Task 3).
3. Requests with a foreign `Origin`, a non-loopback `Host`, or no valid token get 403 and never start work (Task 6).
4. Model output containing `<script>` or `<img onerror=…>` (e.g. copied from a fetched page) renders inert (Task 9).
5. A provider error mid-stream (`OpenAIError`), an empty/whitespace prompt, an unknown model, or a missing API key yields a clear error and leaves the chat usable, not a crashed worker or a hung stream (Tasks 5, 7).

### Task 5: Reply runs

**Files:** Create `src/llm/gui/runs.py`; Test `tests/test_gui_runs.py`.

**Interfaces:** Consumes: `ChatSession`, `ChatStore`, `Delta`. Produces:
- Event dicts: `{"seq": int, "type": "text"|"reasoning"|"tool_call"|"tool_result"|"notice", "text": str}` mirroring `Delta`; plus `{"type": "usage", "prompt": int, "completion": int}`, `{"type": "error", "text": str}`, and a final `{"type": "done", "cancelled": bool}`. `seq` is the 0-based index in the run's buffer.
- `class ChatRun(chat_id: str, session: ChatSession, store: ChatStore, prompt: str, owner: str)`: `start() -> None`, `async def subscribe(after: int = 0) -> AsyncIterator[dict]` (replays `buffer[after:]`, then live until `done`), `cancel() -> None`, `finished: bool` property, `events: list[dict]`.
- `class RunBusy(Exception)`; `class RunManager(grace_seconds: float = 15.0)`: `start(chat_id, session, store, prompt, owner) -> ChatRun` (raises `RunBusy` if that chat has an unfinished run), `get(chat_id) -> ChatRun | None`, `running_ids() -> set[str]`, `heartbeat(owner: str) -> None`, `reap() -> None` (cancels unfinished runs whose owner's last heartbeat is older than `grace_seconds`), clock injectable for tests.

Behaviour: the worker thread runs `session.stream(prompt)` inside `contextlib.closing`; before iterating it appends `Message("user", prompt)` to the store itself and treats that as already persisted; after each delta that is not `text`/`reasoning`, and at the end (also on error/cancel), it appends any `session.messages` not yet persisted (ChatSession adds the assistant message before its `tool_call` delta and the tool message before `tool_result`). `OpenAIError`/`LLMError` become an `error` event followed by `done`. Cancellation is checked between deltas. The worker must never block the event loop; subscribers wake promptly.

### Task 7: HTTP API

**Files:** Create `src/llm/gui/app.py`; Test `tests/test_gui_app.py`.

**Interfaces:** Consumes Tasks 3–6. Produces `create_app(registry: Registry, store: ChatStore, token: str, port: int, *, runs: RunManager | None = None) -> Litestar`, with the Guard on every route (static included). Routes (JSON unless noted; `owner` is a random per-page id from the browser):
- `GET /api/state` → `{"backend": ui.search_status(), "providers": [{"name","title","ready"}], "default_model": str | None}`
- `GET /api/models/{provider}` → `list[str]` from `catalog.list_models` (404 unknown provider)
- `GET /api/chats` → `[{"id","title","updated","model","running"}]`
- `POST /api/chats` body `Settings` fields → `{"id"}`; 400 if the model cannot be resolved or its key is missing (message from `LLMError`)
- `GET /api/chats/{id}` → `{"id","settings","messages","running"}`; messages include `reasoning` and `reasoning_seconds`
- `DELETE /api/chats/{id}` (cancels any run first), `204`
- `PUT /api/chats/{id}/settings` body `Settings` → `204`; `409` while a run is active; validates via `apply_settings` before persisting
- `POST /api/chats/{id}/reply` body `{"prompt","owner"}` → `text/event-stream` of the run's events (`data: <json>\n\n`); `400` for empty/whitespace prompt, `409` if busy, `404` unknown chat — Review Focus 5
- `POST /api/chats/{id}/attach` body `{"after": int}` → same stream replayed from `after`; `404` if no run
- `POST /api/chats/{id}/stop` → `204`; `POST /api/heartbeat` body `{"owner"}` → `204` (also triggers `runs.reap()`)
- `GET /` → `static/index.html`; `GET /static/{path}` serves `static/` (no path escapes).
Sessions are cached in memory per chat id (built with `build_session` on first use); the stream endpoints are tied to the request only for delivery, never for the lifetime of the run.
